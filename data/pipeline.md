# Пайплайн проекта

Готовим «экзамен» для нейросетей, которые работают с кодом. Существующие тесты проверяют только одно — умеет ли модель написать функцию по её описанию. Мы же хотим проверить то, чем программисты занимаются каждый день: понять чужой код, найти ошибку, переписать старое по-новому, оценить последствия правки.

## 1. Собираем сырой материал

Идём в открытые репозитории на GitHub и берём оттуда куски настоящего кода. Отдельно берём каталоги известных уязвимостей (Snyk, GitHub Advisories) - там уже готовые примеры «плохого» кода с описанием проблемы. Плюс используем инструменты, которые автоматически портят чистый код (это называется мутационное тестирование) - получаем много кейсов «было/стало» с заранее известным правильным ответом.

## 2. Чистим и проверяем данные

Убираем дубликаты. Главное - проверяем, что наши примеры не попались моделям на обучение. Иначе модель просто вспомнит ответ, а не решит задачу. Сравниваем куски кода по «отпечаткам» (эмбеддингам) и выкидываем совпадения с известными обучающими наборами.

## 3. Собираем сам датасет — пять заданий разной сложности

Каждый пример - это одна строчка в файле формата JSONL. Всего минимум 500 примеров, на трёх языках (Python, Java, C++):

- **Задание 1** - найти и исправить мелкую ошибку (опечатка, забытое двоеточие, неиспользуемый импорт).
- **Задание 2** - найти дырку в безопасности (например, SQL-инъекцию) и назвать её тип по стандартному каталогу CWE.
- **Задание 3** - переписать старый код по-современному, ничего не сломав.
- **Задание 4** - понять, что в проекте сломается, если поменять одну функцию.
- **Задание 5** - прочитать сложный алгоритм без комментариев и объяснить, что он делает и насколько быстро работает.

## 4. Универсальный «переходник» к нейросетям

Пишем один Python-класс, за которым прячутся все модели - OpenAI, GigaChat, локальные модели через vLLM. Остальному коду всё равно, кто отвечает: он просто отправляет вопрос и получает ответ. Так все модели тестируются в одинаковых условиях, с одинаковыми инструкциями - сравнение получается честным.

## 5. Оцениваем ответы

Для каждого задания - своя метрика. Задание 1 сверяется по точному совпадению строки. Задание 2  -правильно ли модель угадала тип уязвимости. Задание 3 - прогоняем сгенерированный код через готовые тесты внутри Docker-контейнера (если модель случайно напишет что-то опасное, песочница защитит систему). Задание 4 - доля правильно найденных файлов. Задание 5 - насколько объяснение модели похоже на эталонное.

## 6. Собираем итоговую таблицу

Получаем лидерборд: какая модель на каком задании насколько хороша, сколько времени тратит на ответ, сколько стоит прогон в долларах за миллион токенов. Дополнительно проверяем bootstrap-методом, что разница между моделями (например, 72 % против 70 %) - не случайность на маленькой выборке, а реальная закономерность.
